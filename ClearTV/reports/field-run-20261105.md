# Запуски на реальном телевизоре — разбор отчётов (2026-11-05)

Источник: `ClearTV-reports-20261105-0809.zip`, присланный человеком у телевизора после запуска `FULL.cmd`
(ClearTV 0.1.0). Сами отчёты с устройства (IP, список приложений) в репозиторий не кладутся — здесь выводы.

Ход `run-all`: диагностика 7 с → установка 5 с → проверка 67 с → **полная настройка пропущена**: ворота
требуют PASS по `installed`, `cold_start`, `dpad_navigation`, а `dpad_navigation` упал. Главный экран
телевизора не менялся, пакеты не отключались (журнал содержит одну запись `install-apk`). Это и есть
ожидаемое поведение ворот.

## Что прошло

- Установка и запуск: `am start -W` TotalTime 561 мс, первый кадр 308 мс; тёплый запуск быстрее.
- «Все приложения»: 15 видимых приложений (10 служебных пакетов Сбера скрыты по умолчанию).
- Системные настройки открываются; HDMI-вход открывается штатным `InputPlaybackActivity`.
- RAM: PSS 56,1 МБ. После `am crash` главный экран поднялся без безопасного режима.

## Что упало и почему

1. **Пустой ряд избранного** (`dpad_navigation` FAIL, `open_app`/`reorder` SKIP). Logcat:
   `EVT favorites n=0 visible=0 hidden=10` → `EVT salute_defaults hidden=10` → `EVT favorites n=0 visible=15`.
   Запись первичных настроек Салют ТВ (`hidden`) срабатывала до того, как список приложений попадал в активити;
   слушатель настроек перестраивал ряд по пустому списку и сохранял `favorites=[]` как выбор пользователя.
   Исправлено в 0.1.1: список приложений устанавливается первым, слушатель на время записи выключен, из пустого
   списка ничего не сохраняется, а пустой сохранённый ряд считается ненастроенным, пока пользователь сам его не
   редактировал (`favorites_touched`). Телевизор друга «вылечится» при обновлении без переустановки.
2. **`settings_panel` FAIL**: `input keyevent KEYCODE_MENU` не доходит до приложения (на пульте Салют ТВ
   клавиши MENU нет). Тест переписан на путь пультом: ▲ с дока к кнопкам, ▶▶▶ до «Настройки», OK; запасные
   пути — MENU и `am start … --ez cleartv.open_settings true` (новый хук в приложении; результат WARN, если
   сработал только он).
3. **`frame_stats` WARN**: 73 кадра, 42 рывка (57 %), p50 23 мс; «Slow issue draw commands» 42, GPU-гистограмма
   11–20 мс на кадр, UI-поток не виноват. Причина — заливка 1080p на слабом Mali-G31 три раза за кадр (фон окна,
   фон корневого layout, полноэкранный радиальный градиент с альфой) плюс тени `translationZ`, которые
   тесселируются каждый кадр. В 0.1.1: фон окна — единственный чёрный слой, свечение рисуется только в нижних
   62 % экрана без шва, тени убраны, текст героя без offscreen-слоя, анимация цвета 280 мс. Эффект нужно
   подтвердить повторным `verify.ps1` — здесь он не измерим.
4. Мелочи в отчётах: парсер `dumpsys tv_input` считал тюнер Dtvkit (`/HW19`) физическим входом и не знал
   формат Android 13 без `type=`; CEC читался как «выключен», хотя `hdmi_cec_enabled (int): 1`. Оба парсера
   переписаны и покрыты тестами с реальным форматом. 11 пакетов UNKNOWN оказались RRO-оверлеями
   (`overlayTarget=android`) и модулями APEX — теперь они CRITICAL по структурному признаку (кода нет, трогать
   нечего).

## Второй запуск (08:47, ClearTV 0.1.1): ворота открыты, полная настройка выполнена

`ClearTV-reports-20261105-0847.zip`. Проверка: **PASS 12, FAIL 0, WARN 1, SKIP 1** (105 с). Ряд избранного
появился (10 плиток, авто-порядок), навигация, открытие приложения и перестановка прошли; плавность 19,6 %
рывков (было 57 %), GPU p50 13 мс (было 20); PSS 60,9 МБ. `home_key` SKIP — проверка идёт до назначения HOME.

Полная настройка: `install.ps1 -SetHome` → `cmd package set-home-activity` вернул Success, HOME стал
`com.cleartv.launcher/.ui.HomeActivity`; затем `clean.ps1` поставил заставку ClearTV, запретил оверлей
`ru.sberdevices.services`, включил защиту HOME и порог хранилища. На снимке после этого — главный экран ClearTV.

Три ошибки за кулисами (исправлены в 0.1.2):

1. **Ложный «отказ» set-home.** `resolve-activity` печатает короткое имя `pkg/.ui.HomeActivity`, скрипт сравнивал
   его с полным — записал `set-home-attempt` без команды отката и не включил хранитель HOME. Теперь компоненты
   сравниваются через `Test-SameComponent`; при повторном запуске `install.ps1 -SetHome` достраивает недостающую
   запись `set-home` из снимка состояния (прежний HOME `ru.sberdevices.starlauncher`) и включает хранитель.
   Регрессионный тест воспроизводит именно эту ситуацию.
2. **Чистка прервалась на первом пакете: «телевизор потерял сеть».** На Android 13 `dumpsys connectivity` больше
   не содержит `CONNECTED/CONNECTED`, а печатает `Active default network: 102`. Проверка здоровья честно откатила
   `openbeta` и остановилась; 4 PROMOTIONAL пакета остались включёнными. Парсер понимает оба формата, а при ADB по
   Wi‑Fi ответ телевизора сам доказывает, что сеть есть.
3. **▶ на кнопке «Настройки» уводил фокус в док.** FocusFinder нашёл карточку за правым краем экрана (её левый край
   правее кнопки), ряд прокрутился к плитке 5 и OK запустил VLC — поэтому `settings_panel` открылась только через
   `am start`. Теперь ряд без фокуса предлагает FocusFinder только запомненную карточку для любого направления.

Ещё из отчёта: VLC и VK Видео попали в CRITICAL из-за `TvInputService` (это сервисы превью-каналов, а не HDMI) —
теперь критичны только пакеты входов с типом (HDMI/AV/тюнер). Авто-порядок ряда ставил первыми системные утилиты
(медиаплеер CVTE, приём трансляции); в 0.1.2 первыми идут приложения владельца из `favorites.xml`, затем
установленное пользователем, затем TV-приложения прошивки, утилиты — последними. `verify.ps1` после теста
перестановки возвращает ряд в автоматический режим (`--ez cleartv.auto_layout true`).

## Третий запуск (09:34, ClearTV 0.1.3): приложения скачались, но сборка падала при каждом запуске

`ClearTV-reports-20261105-0934.zip`. Загрузка: SmartTube (33 МБ), Xtra (34 МБ), Happ (64 МБ, пакет
`su.happ.proxyutility`) скачаны с GitHub разработчиков и установлены; RUTUBE — на странице rutube.ru/androidtv
скрипт не нашёл ссылки `.apk` (страница теперь сохраняется в `reports/raw` для разбора); Netflix, HBO Max,
Apple TV, Spotify, Chrome — официального APK нет. Чистка: 4 PROMOTIONAL пакета отключены (сеть больше не
«теряется»). Панель настроек открылась пультом (PASS).

**Авария.** В 09:33:47 `verify.ps1` перевёл ряд в автоматический порядок, и ClearTV начал падать при каждом
запуске: 27 стартов процесса за минуту, `EVT safe_mode on=true reason=crash_loop` шесть раз; безопасный режим
не помогал, потому что падение сидело в самом расчёте порядка. Причина: `sortedWith(compareBy({…}, {…}))` —
`compareBy` с несколькими ключами в stdlib реализован лямбдой (invokedynamic) и заменён заглушкой DxCompat; приложение
вызывает его через фасад `ComparisonsKt`, который *наследует* метод от части `ComparisonsKt__ComparisonsKt`, и
проверка сборки такие ссылки не видела. Последствия: `all_apps`, `home_key`, `ram_usage`, `crash_recovery` FAIL
(процесса нет), а после `install.ps1 -SetHome` в 09:34 телевизор остался с падающим главным экраном.

Исправлено в 0.1.4: сортировка — явный `Comparator`, расчёт порядка обёрнут в защиту (при любой ошибке — порядок
обнаружения), DxCompat записывает унаследованные и делегирующие псевдонимы заглушек (контрольный класс с
`compareBy` теперь отклоняется проверкой), защита HOME и хранитель молчат две минуты после падения, чтобы
сломанная сборка не воевала с телевизором.

Второе наблюдение: обновление APK главного экрана сбрасывает выбор HOME (нажатие HOME показывает выбор
лаунчера, `ResolverActivity`; журнал: `HOME: android/…ResolverActivity -> ClearTV`). Теперь `install.ps1`
возвращает ClearTV сразу после обновления, если он был главным экраном, а защита при виде выбора лаунчера зовёт
хранитель.

По просьбе владельца добавлен режим «Только мои приложения» (включён по умолчанию): на главном экране и в сетке
только YouTube/SmartTube, Netflix, HBO Max, Apple TV, Spotify, Happ, Twitch/Xtra, Rutube, VK Видео, Chrome — те, что
установлены; остальное — в Настройки → Скрытые приложения. Удаление лишних приложений, установленных
пользователем (не прошивки Сбера), — отдельный флаг `FULL.cmd -RemoveOtherApps` (обратимо, `install-existing`).

## Четвёртый запуск (09:57, ClearTV 0.1.4): цикл падений снят, режим «только мои приложения» работает

успела перезапуститься 1877 раз (счётчик запусков в логе); после `adb install -r` 0.1.4 падений нет, безопасный
режим не включался, `crash_recovery` PASS. Ряд: `favorites n=4 … auto=true preferred=4` — SmartTube, Happ, Xtra,
VK Видео; сетка «Все приложения» показывает 4. HOME открывает ClearTV, PSS 42 МБ, панель настроек — пультом.

Хвосты: (1) `frame_stats` WARN на 8 кадрах — безопасный режим включил «Меньше анимации», поэтому кадров почти
нет; 0.1.5 отменяет настройки безопасного режима после обновления (если владелец их не менял сам) и не судит о

## Пятый запуск (10:22, ClearTV 0.1.5): Xtra удалён, два платформенных открытия

`ClearTV-reports-20261105-1022.zip`. Проверка: PASS 11, FAIL 2, SKIP 1; полная настройка пропущена воротами (ранее уже
выполнена). Xtra удалён для пользователя по каталогу (`uninstall-user-app`, обратимо), ряд = SmartTube, Happ,
VK Видео. HOME после обновления подтверждён `set-home-reapply`. RUTUBE: адрес `rutube.ru/androidtv/latest/`
переадресует на `promo.rutubelist.ru` — домен не был в списке официальных, файл не сохранён; домен RUTUBE добавлен.

1. **`crash_recovery` FAIL: после `am crash` кнопка HOME показала выбор лаунчера.** Это Android: когда падает процесс
   стороннего HOME-приложения, система сама стирает его выбор как главного экрана
   (`AppErrors` → `clearPackagePreferredForHomeActivities`), чтобы падающий лаунчер не запер пользователя. Именно это
   и происходило в цикле падений 0.1.3. Теперь тест после падения запускает ClearTV командой, сообщает о сбросе и
   восстанавливает выбор сам (`set-home-activity`), а хранитель считает «недавним падением» только два падения за
   две минуты — после одиночного он вправе вернуть HOME.
2. **Защита главного экрана выбивала из системных настроек** (`EVT home_guard bounced=com.android.tv.settings`):
   пакет настроек владеет и `FallbackHome`, поэтому любое его окно считалось «чужим лаунчером». Теперь защита
   сравнивает класс окна с классами HOME-активностей кандидатов, а не пакет.
3. `dpad_navigation` FAIL — ряд перестраивался в момент теста (удаление Xtra пришло широковещательно на старте
   проверки). Тест ждёт и повторяет попытку один раз.
4. «Меньше анимации» осталось включённым от безопасного режима 0.1.3 (та сборка не записывала, кто его включил);
   0.1.6 снимает его один раз, если владелец не трогал настройку сам.

## «Сделай всё возможное» по Netflix, Spotify, HBO Max, Apple TV (0.1.7)

Что сделано: карточки веб-версий (`web_fallbacks`) — Netflix, Spotify, HBO Max, Apple TV и Twitch открываются в
браузере телевизора, пока нет приложения; правило «Chrome» принимает браузер Сбера; `get-apps.ps1` пробует
официальные страницы Netflix (help.netflix.com) и Spotify (spotify.com) на наличие APK с доменов разработчика.
Что невозможно и не делалось: скачивание этих приложений с APK-агрегаторов; обход проверки сертификации и DRM;
обход региональных ограничений — сервисы не обслуживают Россию. Полноценные приложения — только сертифицированная
приставка в HDMI с зарубежным аккаунтом и VPN.

## Что дальше

Повторить `FULL.cmd` из архива с ClearTV 0.1.7. Прежняя рекомендация по 0.1.4 остаётся в силе: обновление APK снимает цикл падений
(`adb install -r` работает даже пока приложение падает). Прежний план с 0.1.2 остаётся в силе: `install.ps1 -SetHome` достроит запись отката и включит хранитель
(на телевизоре появится запрос «Разрешить отладку?» от ClearTV — «Всегда разрешать»), `clean.ps1` отключит
4 PROMOTIONAL пакета (openbeta, smarthome.promo, starcleaner, survey). Приложения из списка владельца, которых на
телевизоре нет (YouTube, Netflix, HBO Max, Apple TV, Spotify, Happ, Twitch, Rutube, Chrome), появятся на главном
экране, как только их установить — через магазин телевизора или папку `apps\` (`APPS.cmd`).
